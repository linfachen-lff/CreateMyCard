# 批跑模板数据匹配临时旁路说明

本文供后续工程师和编码 Agent 在 `generateWidgetCardTerseDslNested2` 批量视觉评测中排障和继续开发。
完整云侧契约仍以 `docs/云侧方案设计.md` 为准。

## 目标

正式链路会根据 `TaskSpec.dataModelSchema` 判断 Template 必填参数是否可满足，不满足的 Template 会被剔除。
批量视觉评测为了观察模型选择和端侧效果，可以临时跳过这一步候选过滤，避免第二层因为
`requiredLocalTemplateGroups` 为空而提前失败。

该旁路只放宽“候选是否可见”，不会关闭最终 Compiler、安全或协议校验，也不会伪造缺失数据。

## 生效条件

服务端必须同时设置：

```text
WIDGET_SERVICE_ENABLE_WIDGET_BATCH_RECORDING=true
WIDGET_SERVICE_ENABLE_ADVANCED_COMPONENT_DATA_ADMISSION_BYPASS_FOR_BATCH=true
```

端侧 WebSocket 请求还必须同时携带合法的 `batchId`、`caseId` 和 `size`。只有满足这些条件的当前请求
会进入旁路；普通请求仍执行严格 Template 数据匹配。

修改环境变量后需要重启服务。批跑结束后将第二个开关恢复为 `false` 并重启，即可恢复严格模式。

## 关键代码入口

- 请求级旁路上下文：
  `widget_service/cloud/services/advanced_component_pipeline/content_selectors.py`
  中的 `advanced_component_batch_data_admission()`。
- 批跑请求识别与完整 outputSchema 投影：
  `widget_service/cloud/services/widget_generation_service.py`。
- Template 候选过滤：
  `widget_service/cloud/services/advanced_component_pipeline/scope_planner.py`
  中的 `scope_template_ids()`。
- 第二层 Template 分组与 Prompt：
  `widget_service/cloud/services/advanced_component_pipeline/ux_mixed_prompt.py`。
- 最终可信编译和校验：
  `widget_service/cloud/services/cardplan_template/compiler.py`。

当前临时逻辑位于 `scope_template_ids()`：旁路生效时返回当前高级组件在 Registry 中登记的 Template，
否则继续调用 `_template_has_satisfiable_variant()` 按数据严格过滤。

## 安全边界

继续修改时必须保留以下约束：

- 旁路必须是 request-scoped，禁止使用进程级可变全局状态。
- 必须同时受批次记录开关、旁路开关和合法批次参数约束。
- 不得关闭 capability/provider、尺寸、Registry 组合和布局约束。
- 不得放宽可信文本、数值、素材、Action、Template 参数和最终 A2UI 校验。
- 不得由 LLM 编造缺失业务数据。真实必填数据完全缺失时，最终编译仍可失败，这是预期行为。
- 不得改变普通生成请求的行为。

## 验证方法

在 `widget_service` 目录执行：

```bash
PYTHONPATH=cloud .venv/bin/pytest -q \
  tests/test_advanced_component_admission_bypass.py \
  tests/test_advanced_component_pipeline.py

.venv/bin/ruff check \
  cloud/services/advanced_component_pipeline/scope_planner.py \
  tests/test_advanced_component_admission_bypass.py

git diff --check
```

至少确认以下结果：

1. 严格模式下，数据不满足的 Template 仍被过滤。
2. 合法批跑请求且旁路开启时，Registry 中的 Template 候选能够进入第二层。
3. 旁路开关关闭时，即使存在批次上下文也保持严格匹配。
4. 没有 provider 支撑的高级组件不会因为旁路而获准。
5. 最终 Compiler 仍拒绝编造的文本、数值、素材、事件或 Template 参数。

## 常见失败判断

- `Advanced Scope component has no satisfiable trusted Template`：先检查旁路是否满足全部生效条件，以及
  `scope_template_ids()` 是否返回了候选。
- Template 已进入第二层但 Compiler 失败：检查完整 outputSchema 是否确实包含 Template 展开所需的可信事实；
  不要继续放宽 Compiler。
- 普通请求也被放宽：检查调用是否脱离了 `advanced_component_batch_data_admission()` 的上下文，或是否误把
  request-scoped 状态改成全局状态。
- 修改开关无效：确认服务已经重启，并检查请求是否同时携带合法的三个批次参数。
